# Retained toolkit

## Purpose

The Windows Forms-like C++ class API is drawn client-side in the Classic theme.
UI construction is code only. The controls are a pure user library; a session
adapter and root-started preview component bind it to the compositor.
Filesystem-service and Component Manager launch integration are unsupported. UTF-8
decoding follows Unicode Standard 16.0 section 3.9 table 3-7 through User/Text;
font processing follows [FontEngine](FontEngine.md).

## API and storage

`Source/User/Toolkit` provides Application, Form, Control subclasses, Graphics,
Theme and value types. Controls borrow their Application and parent; attaching
does not transfer ownership. Declare application, controls, two pixel arrays
and large font workspaces in static storage on targets. The retained API has no allocation, exceptions, RTTI or persisted format.
The preview component owns its static state and requests bounded RAM Frames
through its private ResourceDomain; it never uses a target heap.
Controls must outlive queued calls, event callbacks and their parent attachment.
Construct and destroy on the UI thread; property operations and detach may be
called from workers. Stop callers and cancel borrowed queued work before
destroying controls. Pointer deletion and heap construction are unavailable.
In-place lambda handlers own small trivially copyable captures; captures of references retain
the caller's ordinary lifetime obligations. Event arguments use Unicode scalar
values and UTF-8 text. Property operations return explicit status codes.

The implementation has one set of bounds in Types.hpp: 128 controls per
Application, 32 children per control, depth 16, 512 UTF-8 bytes per control,
32 list/toolbar items of 64 bytes, 64 queued invocations, 16 timers, 16 damage
rectangles, 8 table rows/columns and maximum 4096 pixels per surface axis.
On the current 64-bit ABIs Application is 5,400 bytes, Control 1,792,
Form 2,672, TextBox 1,816, ComboBox 6,064, details ListView 24,328 and
DemoForm 113,936. The optional FontContext is 1,159,944 bytes plus its lent
cache arena/entries and borrowed font data; one context is reused across all
controls. These are caller-owned objects, never automatic target stack frames.
Two maximum-size 4096-square images require 128 MiB of caller storage; the session adapter additionally refuses dimensions/stride above 4096 and
any native image exceeding the session pool limit of 8,192 pages (32 MiB).
Its refusal precedes pool allocation in the component. It cannot lend the
pure library's theoretical 4096-square image through this protocol.
Full queues reject new requests; no queued request is silently overwritten.
Large raster/layout scratch belongs to an injected FontContext. Strings are
validated before mutation, preserving the old value on invalid input or limit.

## Threading and events

An injected IThreadHost identifies the UI thread, locks the bounded queue,
wakes the event source and waits for synchronous completion. Its wait and wake
must implement persistent notifications (a wake before a wait is not lost).
Application::Invoke runs inline on the UI thread; other threads enqueue and
wait. BeginInvoke owns its capture until execution. Control property calls,
reads and handler registration use Invoke. All callbacks, input, layout, paint
and timer events execute on the UI thread. Callers must keep pumping the UI
loop while workers make synchronous calls and must not join such workers from
an event callback. Queue locking never encloses a callback. Shutdown refuses
new calls and completes queued synchronous requests with a stopped status.

IEventSource supplies nonblocking Poll and Wait/Wake; Application::Step drains
a bounded snapshot of work, polls one input and services bounded timers.
Run calls Wait between steps; the fake host tests exercise the same path.
SessionAdapter translates surface-local signed pointer coordinates, button
edges and wheel deltas, HID key edges and US/JIS layout scalars. Printable
scalars become UTF-8 through TextBox; Ctrl/Alt/GUI chords do not insert text.
Focus loss cancels capture and repeat, releases hover/focus, and suppresses
unfocused makes; focus regain restores a still-registered control. Primary
button capture and activation are independent of secondary edges. DoubleClick
is generated by Application using Theme.DoubleClickPeriod (500 ms) and
DoubleClickDistance (4 pixels on each axis), on the second primary press.

## Rendering, theme and layout

Form borrows two disjoint, equal-size surfaces and an IPresenter. A successful
Present lends that image; ReturnImage releases it. A busy presenter retains
damage for retry. Only writable images are drawn. Prior image damage is copied
forward before painting the next image; Paint callbacks receive a clipped
Graphics. Child clipping and reverse z-order hit testing use the retained tree.
Overflowing damage lists conservatively union into one rectangle.

Theme is the sole source of colours, metrics and font selection. Classic()
takes the default palette from the session Palette header. A caller opens
Vegur from Data/Fonts/Vegur with User/Font and lends a FontContext; absent or
failed glyphs use Bold8x16. Theme changes invalidate all forms. Graphics offers
clipped fills, lines, bevels, text alignment/ellipsis and alpha-blended raw
RGBA/BGRA Image views. PictureBox::SetDecodedImage borrows validated RGBA
from User/Imaging through a thin adapter; decoding and font-file loading stay
outside the control API. See [Imaging.md](Imaging.md) for codec bounds.

Bounds are absolute parent-client coordinates. Anchor uses the last explicitly
assigned bounds and parent size; Dock consumes available client space in child
order. Padding/margin, AutoSize, FlowLayoutPanel and TableLayoutPanel share
the same bounded layout pass. Focus uses effective ancestor visibility and
enablement, tab order, Tab/Shift+Tab and control-specific arrows; Space/Enter
activate, Escape cancels popups, and Alt mnemonics are optional.

## Session binding

`Session::ClientConnection` owns an epoch-bound client transport and two native
output pools, one complete image per pool.
Each pool has up to sixteen owned RAM Frames of up to 512 pages, mapped
writable by the producer and attached with Map only by the session codec.
The producer uses AddressPoolSpan and the native output size, never a test
rectangle. ResourceExhausted reports allocation refusal; smaller
runs are retried within the sixteen-Frame bound. A failed partial
allocation exits and is reclaimed by the component's domain drain.

`Toolkit::SessionAdapter` implements Application's event source and Form's
presenter. It defines only returned images, presents complete images with the
Form's bounded damage, and returns them on ImageReturned. Arrange changes
both views' metadata, invalidates the whole new client rectangle, and supplies
the latest serial to Present. It never writes a lent image, including while
maximizing/restoring. Resize handlers and anchoring use the existing layout
path. CloseAsked invokes cancellable Form::Close (Closing/Closed); accepted
close destroys the surface once and continues draining returned images before
stopping Application. Timers and key repeat use the session's timer-only
WaitSet, at most ten milliseconds per idle turn; Application's
millisecond deadlines and missed-tick coalescing are retained.

`RunSessionDemo` owns one Application, adapter and DemoForm in a separate
component on both ISAs. Its four-column 600x314 client displays 28 sample
controls and fits the native 640x400 desktop. The preview uses the root-supplied
Vegur-Regular tail through Read-only/Map-only capabilities and the existing
Bold8x16 glyph fallback. A separate 301-page RAM workspace holds the font
context, Face, 64 cache entries and 64 KiB cache. The single UI-thread host is
valid only for this one-thread grant; worker hosts remain injected API owners.

The child budget is exactly `private PT_LOAD pages + stack/start pages + 8
font-tail pages + 301 workspace pages + 2*native-image pages`, for both
committed and resident caps. The linked private segment is 31 pages. This is
7,543 pages at AMD64 2560x1440 (3,600 per image), and 849 pages at IA-64
640x400 (250 per image). Shared RX pages are retained once under root's
existing image policy: 31 on AMD64, 72 on IA-64. Object limits are 35 Frames
(two pools of sixteen plus private data, stack/start and workspace), five
MemoryObjects, one each of AddressSpace, CapabilitySpace, ProtectionDomain,
ResourceDomain, Thread, Endpoint and WaitSet, zero FaultChannels, no Code,
no children and no large page-table arena. Root retains one preview manager
reply Endpoint. Every additional toolkit window requires another connection,
component and child budget; the session's boot-log remains root-owned.

Root's ToolkitLaunch helper registers the trusted toolkit-demo title, launches
the component and drops it before domain drain. DropClient has
a two-second acknowledgment bound; failure stops the compositor and its
existing product recovery drains borrowed pins before collecting the client.
A compositor restart starts a fresh preview Application. State persistence and
Component Manager relaunch policy remain outside this integration.

Host SessionAdapterTests exercise input, UTF-8, focus/capture, click timing,
resize/maximize/restore, immutable lent pixels, canceled/duplicate close,
limits and timer coalescing. ToolkitSession VM scenarios use real PS/2 input,
check button/TextBox/CheckBox/ListBox state, maximize/restore/move/close, and
compare the full client capture with Tools/Build/ToolkitRender. This oracle
shares the toolkit renderer and font engine; reviewed host goldens supply the
independent pixel corpus.

## Unsupported functionality

Shared-library packaging, Component Manager application launch, clipboard, IME/bidi/grapheme shaping, accessibility, a designer, persisted
theme format and image-file loading are unsupported. Encoded image parsing
is available separately in the pure Imaging library. File-dialog service
integration must use an injected capability interface, never global filesystem
authority. The control inventory includes GroupBox, scrolling Panel, TabControl,
SplitContainer, flow/table panels, ListBox, details ListView, TreeView,
NumericUpDown, ProgressBar, TrackBar, ScrollBar, LinkLabel, MenuStrip,
ContextMenu, StatusBar, ToolTip, multiline/password TextBox and MessageBox.
Nested menus, column sorting/resizing, table spans, rich text, visual password
reveal and nested modal dialogs are unsupported. Popup lists are
clipped to the form; file enumeration is limited to one bounded page (32
entries). File-dialog calls are synchronous injected calls, suitable for a
local stub; a real transport must arrange UI-friendly request completion.
File service tokens and selected grants have service-defined ownership and
must be closed/released by that service or the caller, never by guessing an
ABI in the toolkit.

## Compatibility and policies

The toolkit uses scalar-boundary text editing, fixed storage limits,
nearest-neighbour image scaling, first-in-child-order docking, row-major equal
table cells unless weights are supplied, UI-thread construction/destruction,
form-clipped popups, no clipboard, and synchronous cross-thread calls returning QueueFull instead of waiting for queue space.
Widget behaviour is intentionally similar to Forms, without claiming binary
or exact Win32 behavioural compatibility. These policies introduce no persisted
file format or security grant.

## API example

```cpp
// Static on the freestanding target; all borrowed storage outlives the tree.
Toolkit::Application app{threadHost, eventSource, Toolkit::Theme::Classic(&vegur)};
Toolkit::Form form{app};
Toolkit::Button button{app};
static_cast<void>(form.Bind(firstImage, secondImage, presenter));
static_cast<void>(form.Add(button));
static_cast<void>(button.SetBounds({16, 16, 120U, 28U}));
static_cast<void>(button.SetText(Toolkit::Utf8("Apply")));
static_cast<void>(button.On(Toolkit::EventKind::Click,
    [&model](Toolkit::Control&, Toolkit::Event&) noexcept { model.Apply(); }));
// Run pumps the application loop until shutdown; Step does bounded work.
static_cast<void>(app.Run());
```

For worker code the same SetText/SetBounds/On/Focus/State operations synchronously
marshal to that loop. Check Status on mutation or use CopyText for an explicit
read status; convenience State/Value return an empty/zero value if dispatch
fails. Explicit BeginInvoke supports captures up to 32 bytes and rejects a full
queue. Handler captures have the same bound. Only Ui-prefixed primitives and
UiTheme/UiFocus are thread-confined; they exist for drawing custom controls and
for host diagnostics. Run/Step and constructors are thread-confined lifecycle
operations. A timer interval and Now/deadlines use the injected source's common
millisecond scale; repeating timers coalesce missed ticks. Timer identifiers do
not wrap into reuse.

Theme.DefaultWidth/DefaultHeight determine initial control sizes; all widget
colour, spacing, bevel, indicator, arrow, popup-row, text and timing metrics
come from Theme. PixelSize in the font engine is derived from Theme.FontSize.
The font context, masks and cache are single UI-thread owners. With 128 controls
registered, excess construction creates an unattached control whose Add fails;
Application::Register and all bounded collections expose Limit explicitly.

Verification uses ordinary host test discovery and target unlinked user source
lists. Five test executables cover exact stored RGB goldens in both font modes,
layout at multiple widths, mouse/keyboard scripts, source-loop wakeups, modal
capability stubs, deterministic full-image carry comparison, FIFO/concurrent
marshaling and queue/timer saturation. Eight seeds replay 10,000 operations each
against focus, parent depth, text selection and queue invariants. The target
stack gate checks O0 and O2, including the code-only DemoForm setup helpers.
