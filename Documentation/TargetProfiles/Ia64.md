# IA-64 Target Profile

This profile supports the project's Montecito VM with one through four CPUs.
The [boot contract](../Architecture/BootContract.md) defines the firmware boundary;
[Implementation Status](../ImplementationStatus.md) records integration and tests.

## Compiler and ABI

| Item | Validated configuration |
| --- | --- |
| Compiler | GCC 15.3.0, `ia64-linux-gnu-g++` |
| Binutils | 2.46.1, `ia64-linux-gnu-*` |
| Language | C++23, `-ffreestanding -nostdinc -nostdinc++` |
| Object ABI | ELF64 IA-64 little-endian, LP64, eight-bit bytes, signed plain `char` |
| Kernel calls | GNU IA-64 System V; valid `r1`, P64 descriptors, aligned memory/register stacks |
| Firmware ABI | PE32+ `pei-ia64`, subsystem 10, UEFI P64 |
| Code generation | `-mno-sdata -fno-pic -mtune=itanium2 -fno-jump-tables`; kernel also `-mfixed-range=f32-f127` |

`itanium2` is the available family tuning, not Montecito-specific scheduling.
Override tool discovery at configuration with `IA64_CXX`, `IA64_LD`,
`IA64_OBJCOPY`, `IA64_NM`, `IA64_READELF` and `IA64_OBJDUMP`
(`Tools/CMake/Toolchains/Ia64.cmake`).

[`Foundation/Types.hpp`](../../Source/Foundation/Types.hpp) defines fixed-width
integer aliases, `UIntPointer` for addresses, and `Size` as the type of `sizeof`.
Signed integers use two's complement. Pointers and `UIntPointer` use flat eight-byte addresses;
pointer conversion preserves byte-address order within the same allocated object.
Verified size/alignment pairs
are 16/8 for `CapabilityHandle`, 48/8 for `CapabilityDescriptor`, and 32/8 for
`PhysicalPageRange`; `RevocationDomainId` is eight bytes. External formats use
explicit field encoding.

The EFI entry is a function descriptor in `.opd`. The image has exactly `.text`,
`.rodata`, `.opd`, `.reloc`, `.data`, and `.bss`. Three `DIR64` fixups cover entry
code, GP, and the retained function-pointer reference. `__gp` is fixed at RVA
`0x180000`; the build rejects conflicting definitions or uncovered relocations.
The ESP holds stripped pager and user ELFs separately. The boot application reads
and checks them into one retained LoaderData region; staging consumes that region
before translation takeover ([boot file contract](../Architecture/BootContract.md)).

The loader base must be 64 KiB aligned; sections retain 4 KiB granularity. Build
checks run production mapping planners over the complete loader-alignment period:
the worst geometry, with the bootstrap and run-time memory reservations, must fit
32 DTRs and 32 ITRs and reject one DTR fewer
([translation-register budget](../Architecture/Ia64TranslationRegisterBudget.md)).

## Runtime and permitted extensions

- Target images link no external standard library or compiler runtime.
  Exceptions, RTTI, guarded local-static initialization, `__cxa_atexit`,
  stack protectors, and unwind tables are disabled.
- The kernel uses only the low floating-point partition (its compiler uses
  f6-f15 for integer multiply and divide): `-mfixed-range=f32-f127` keeps the
  high partition, which holds user threads' state, out of compiled code, and
  Verify `Ia64KernelLowFloatingPartition` admits f32-f127 only in the PL3 entries'
  spill and fill and the native preemption probe
  ([high floating-point partition](../Architecture/Ia64KernelContext.md#high-floating-point-partition)).
- User threads own f2-f127 ([high floating-point partition](../Architecture/Ia64KernelContext.md#high-floating-point-partition)): all except the
  synthetic probe launch with PSR.dfl and PSR.dfh clear, so compiled user code may use floating point, and
  integer multiplication and division, which GCC computes in f6-f15. The kernel runs under its own fpsr at every PL3
  entry (Verify `Ia64KernelFloatingPointStatus`), keeps f2-f127 across interruptions and context switches, and hands
  a PL3 Floating-point Fault or Trap (0x5c00, 0x5d00) to the thread's supervisor through the exception entry; a
  fault that would need a software assist (FPSWA) terminates the thread too. Verify `Ia64UserFloatingPointLaunch`
  pins both launch PSRs.
- Namespace-scope state requires constant initialization. Link checks reject
  constructor/destructor arrays. Retained owners use explicit placement
  construction; target startup has no heap.
- Project C ABI memory primitives close compiler-generated copies and fills.
  Both compile-check closures and firmware kernels link `Runtime/CxxAbi.cpp` and
  `Platform/FatalTrap.cpp`. Final images must contain non-empty executable global
  symbols for `__cxa_pure_virtual` and `FatalTrap`, and must have no unresolved
  symbols (including weak vtable references). `FatalTrap` executes `break 0`
  via `__builtin_trap`; after IVT initialization, the kernel break handler
  rejects kernel-mode breaks and fail-stops.
- GCC atomics belong to `Platform/Synchronization` and must compile to inline,
  lock-free instructions. `__builtin_offsetof`, `__builtin_unreachable`, and the
  target `__builtin_trap` are permitted in their platform adapters.
  `__builtin_clear_padding` (spelled `ASTERIA_CLEAR_PADDING`, from
  `Foundation/Compiler.hpp`) is limited to canonical atomic publication of
  trivially copyable diagnostics.
- `used`/`section` attributes retain native entry code and data. Audited assembly
  belongs to firmware calls, translation/cache ownership, interrupt/syscall and
  context entry, user transport, MMIO, diagnostic adapters, or the boot entropy
  source (an `ar.itc` read; IA-64 has no random-number instruction).
- `noinline`/`noipa` (spelled `ASTERIA_NOINLINE_NOIPA`) retain checked entry
  and stack boundaries in the common run loop and IA-64 transition helpers. A
  compiler ignoring them must still pass the same dependency, disassembly, and
  stack gates.

## Execution and memory constraints

Firmware validates zero-fill and loaded-image ownership before constructing
kernel state. Boot services end permanently at successful `ExitBootServices`.
SAL/PAL values survive only as owned validated records; contained firmware
addresses do not authorize executable mappings.

The [firmware handoff](../Architecture/Ia64FirmwareHandoff.md) owns SAL capture,
PAL calls, initial stack/RSE takeover, and translation installation. Its physical
call environment excludes interrupts and preemption. PAL requires 8 KiB of free
stack; SAL registration requires at least 17,408 bytes free in each memory stack
and RSE store at adapter entry, including its 1,024-byte reserve. The EFI stack
minimum is 128 KiB. Local PAL purge domains are bounded to 65,536 operations.

The [initial address space](../Architecture/InitialAddressSpace.md) uses native
region registers and ITR/DTR resources. RR0 is the shared RID `0x2000` anchor;
private runtime RIDs are never reused. Firmware ITR(0) and SAL handoff RIDs are
reserved explicitly. A virtual PAL caller requires explicit PAL mappings; the boot path calls PAL in physical mode.

The [BSP memory owner](../Architecture/Ia64BspRuntimeMemory.md) retains shared and
private roots, translation ledgers, per-CPU bindings, and controllers for boot
lifetime. Root changes must preserve the shared code/data/stack/RSE corridor.
[Kernel contexts](../Architecture/Ia64KernelContext.md) use distinct owned
16-64 KiB memory-stack and RSE ranges. The current frame gate is 512 bytes per
function at O0 and O2; this does not prove whole-path interrupt nesting bounds.

ACPI accepts extended Local SAPIC entries and the legacy 12-byte form, deriving
the latter's UID from `ProcessorId`. SAL capture accepts combined runtime
code/data descriptors but still requires runtime attributes, readable,
nonoverlapping storage, and IA-64's 8 KiB runtime/ACPI geometry.

## Concurrency, interrupts, and I/O

Shared memory uses platform atomics and locks. Spin locks are neither fair nor
bounded under contention; callers exclude same-CPU preemption and reentry.
ISRs cannot acquire registry locks, allocate, block, or run unbounded work.
[Endpoint bounds](../Architecture/EndpointQueue.md#concurrency-and-bounds) exclude
contended spin time and do not make those operations interrupt-safe.

The native timer uses `ar.itc`, `cr.itm`, and `cr.itv`; stop its time domain before
64-bit wrap. Interrupt entry publishes bounded evidence, leaving TimerQueue and
Notification delivery to normal context. AP service and shared-root shootdown
notification are polled. General interrupt-driven AP scheduling and IPI shootdown
remain outside this profile.

The [BSP runtime](../Architecture/Ia64BspKernelRuntime.md) owns default PL3 image
launch, cooperative AP service, and optional timer/WaitSet and preemption probes.
[Syscall entry](../Architecture/Ia64UserSystemCallRuntime.md) preserves the PL3
frame and RSE partition before common dispatch and `rfi` return. The heavyweight
[page-fault entry](../Architecture/Ia64PageFaultEntry.md) captures and stops; its
transport is not published by default boot.

Physical MMIO uses checked DWORD readers/writers backed by uncached `DeviceRegion`
authority. The adapters validate PAL physical width, mask `PSR.i`, quiesce RSE,
clear `PSR.dt`, use the bit-63 UC alias, and restore entry state. Reads use
`mf; ld4.acq; mf.a`; writes use `mf; st4; mf.a`. Local SAPIC IPI stores use
`mf; st8; mf.a`. The debug UART uses a separate bounded physical byte-access
path and stays unmapped in the runtime root. Its transmit and line status
registers come from the firmware's DBG2, DBGP, HCDP or SPCR table, which the
loader reads and BootInfo carries ([Debug port](../Architecture/BootProtocol.md#debug-port));
without one it is itanium2-vpc's debug UART at `0x47f0001000`.

[PCI/AHCI bootstrap](../Architecture/PciEcamConfigurationSpace.md) retains separate
ECAM and ABAR authority. Its one-disk polling diagnostic uses coherent identity
DMA with no IOMMU: one 4 KiB command/FIS/table page and one 4 KiB read-data page
inside writable image storage. Both remain reserved while controller ownership
is possible. The profile does not support non-coherent DMA.

Recoverable operations return typed status. Pre-exit failures may return an EFI
error; post-exit kernel failures emit bounded diagnostics and stop. Supported
PL3 faults use the [user-fault entry](../Architecture/Ia64UserFaultEntry.md) and
supervisor channel. Watchdog and power-transition paths are implemented;
persistent crash records and broader recovery policy are unsupported. See
[watchdog](../Architecture/Watchdog.md) and [power transitions](../Architecture/PowerOff.md).

## Emulator and validation

| Item | Configuration |
| --- | --- |
| Emulator | `IA64_QEMU` (configured emulator path), QEMU 11.0.50 development tree with the project's opt-in machine additions (virtio-iommu, eight INTx lines; DMA isolation) built in its own directory |
| Machine / CPU | `itanium2-vpc` / `montecito` |
| Firmware | `IA64_FIRMWARE` (configured firmware path) |
| VM matrix | 1-4 CPUs, SATA, and four-CPU forced relocation; 512 MiB per VM |

Other machine aliases are outside this matrix, except `hp-i2000` (Merced, 460GX,
2 GiB, `usb=off`), whose production boot to the root service on one and two
CPUs are the cases of the `Ia64I2000` suite: its diagnostic channel is COM1,
which its SPCR and HCDP name. The emulator's `-debug-port` creates its chardev on
that machine but attaches no UART and publishes no DBGP (its XSDT lists FACP,
APIC, SRAT, SLIT, HCDP, SSDT and SPCR), so the case attaches it to a file and
requires it to stay empty; itanium2-vpc's DBGP names its debug UART as system
memory `0x47f0001000`, 8-bit registers, bit offset 0, access size 0 (byte).
That machine has no ECAM, so its boot binds no PCI function, reads no AHCI disk
and publishes no scanout. Each case runs in its own run
directory with its own ESP copy, talks to QEMU through QMP and debug-channel
socket pairs, and retains logs and memory evidence. The kernel reports each
completed boot step as a neutral `ASTERIA:STAGE:<NAME>` event and stores what
its diagnostic scenarios observe (processors, PCI, AHCI, AP runtime, shared-root
shootdown, probe timers, native preemption, object management and the
collections that reclaim its objects) in the evidence record
`Ia64EvidenceRecord`, whose address it reports once as
`ASTERIA:EVIDENCE:0x<address>`; FAIL/ERROR/FAULT lines remain the only kernel
verdicts. The VM runner (`Tools/Vm/RunVmTests.py`) checks the stage order,
judges the record against the case, QEMU and the build's constants, and owns the
stopped-state oracles; the [README](../../README.md#firmware-and-vm-tests)
lists commands and environment overrides. Default image, synthetic WaitSet/RSE,
and native-preemption scenarios are separate. The `AP-RENDEZVOUS` stage attests
the AP-side checks; a BSP monitor snapshot does not directly inspect every AP's
RR/TR state.

IA-64 fault delivery: every user launch sets `PSR.di`
(Disable Instruction Set Transition). A PL3 `br.ia` raises the native
General Exception's Disabled Instruction Set Transition fault and reaches
that thread's supervisor, rather than entering an unsupported IA-32 state.
PL3 cannot clear `PSR.di` (*IA-64 Architecture Software Developer's Manual*,
revision 1.1, July 2000, Vol. 2 §3.1; Vol. 3, "br", Operation).
